# 記録どうしをつなぐ

## 約束

- **書くのは、各記録の「関連」の欄だけ。** その記録から先へのリンク（相談・文字起こし・会話・実験・決定・解析・コミット）は、その記録を書いた会話の Claude が書く（研究者が書き足してもよい）。何に関係するかを一番知っているのは、その記録を書いた会話だから。
- **逆向きのリンクと一覧は、このスクリプトが作る。** 人も Claude も直接書き換えない。書く場所を片方にすると、食い違わない。
- **スクリプトが置き換えるのは、自分が書いた形の囲みだけ。** 見出し「この記録を指しているもの（自動）」のすぐ後に始まりの印があり、終わりの印までの行がスクリプトの書く形（`- 相談：…` など）だけのものを、囲みとみなす。印とみなすのは、コードの外で、行に単独で置かれたものだけ。本文で印に触れた所や、本文（コード）に書いた囲みの例は置き換えない。
- **囲みが崩れている記録には書き込まず、知らせる。** 見出しを書き換えた、囲みの中に人が書き足した、印の片方が欠けた、といったとき。見出しと始まりの印があって終わりの印が無いときは、いつも「崩れている」として出す。`records/links.md` の「末尾の囲みが崩れている記録」と `--check` に出る。崩れた囲みの中のスクリプトの行は、その記録から先へのリンクとして読まない（前に書いた逆向きのリンクを、その記録が書いたリンクと取り違えないため）。見出しから囲みの終わりまでを消せば（書き足した行は本文に移す）、次に作り直したときに新しく足される。
- **書き込めない記録は飛ばして、知らせる。** 開けない、保存できない、読み出しのみ（どの OS でも）、といったとき。ほかの記録は続ける。
- **切れたリンクとして出さないもの**：
  - git に入れないフォルダ（`.gitignore` で外したもの。会話の生の記録、`export/` など）へのリンク。この PC にそのフォルダが無くても出さない。別の PC にだけあることがあるため。
  - 会話の要約の題の行（1 行目）と、冒頭の `auto` の囲みの中にあるリンクと記録のパス（スクリプトが書いたもの）。無いファイルも無い印も、切れたリンクとして出さない。
  - 自動で作る一覧そのもの（`records/links.md`、`chats/README.md`、`records/sessions/README.md`）へのリンク。
- **`{{…}}` は、リンクを探すときに読まない。** ひな形の書き込み欄を、リンクと取り違えないため。
- **記録の名前に「#」や「%」があってもよい。** スクリプトが作るリンクでは、`#` を `%23`、`%` を `%25` に直して書く（`#` を印の始まりと読み違えないため）。手で書くリンクも同じにする（下の「「関連」の欄の書き方」）。
- **二つの PC で、同じハブを git で行き来するとき**：`records/links.md` と `chats/README.md` は、`.gitattributes` の `merge=union` で、両方の PC の行を残してマージされ、次にスクリプトが動いたときに作り直される。もう一方の PC の変更をマージしたら、コミットの前に、`harness-session-archive` のスクリプトとこのスクリプトを動かす（README の「構成」の二つの PC の段）。スクリプトが書く囲みの中に、git の衝突の印（`<<<<<<<` から `>>>>>>>` まで）がそろって入っていれば、その囲みを作り直す。衝突が囲みの印の外まで続いているときは、その記録を「囲みが崩れている」として知らせ、書き込まない。先に手で衝突を直す。
- **途中で止められた実行が残した一時ファイル**（`.gitignore` の `.*.tmp` に当たるもの）は、次に動いたときに片づける。手で動かしたときに Python が 3.10 より古ければ、そう知らせて止まる。

| 作るもの | 中身 |
|---|---|
| 各記録の末尾の「この記録を指しているもの（自動）」 | `<!-- links:start -->` 〜 `<!-- links:end -->` の囲み |
| `records/links.md` | 記録ごとの「指しているもの」「指されているもの」、切れたリンク、相談の記録につながっていない文字起こし |
| `chats/README.md` | 文字起こしごとに、それを使っている相談・会話・決定など |

- 逆向きを書き込むのは、相談・実験・会話の要約・経緯の記録・決定。
- 文字起こし・論旨の正本・指示書と報告には書き込まない。文字起こしは本文を変えないため、論旨は正本を汚さないため。
- 逆向きのリンクは `records/links.md` と `chats/README.md` で見る。

## 「関連」の欄の書き方

記録の本文の終わり近く（自動の囲みより前）に置く。リンクはその記録からの相対パスで書く。名前に空白や括弧があるパスは `<…>` で囲む。スクリプトは、`<…>` で囲まないリンクの先でも、対になった半角の括弧を一重までは読む。

- **名前の「#」は `%23`、「%」は `%25` と書く**（`<…>` の中でも）。そのまま書いた「#」は、印（`#d-…`）の始まりとして読まれるため。例：`[メモ#2](<../../../chats/メモ%232.md>)`。
- 切れたリンクを直す統括も、同じ書き方で直す。

```
## 関連

- 文字起こし：[レビュー（第2章の草稿）](<../../../chats/レビュー（第2章の草稿）20260115.md>)
- 会話：[2026-01-10_1a2b3c4d](../../sessions/2026-01-10_1a2b3c4d.md#d-20260115-143000)
- 実験：[exp-pilot](../../experiments/exp-pilot/README.md)
- 決定：[hub/decisions.md](../../../hub/decisions.md)（予備実験を先に行う）
```

スクリプトは既知の記録の名前で探すので、次の書き方でもつながる（ただし、クリックできるリンクで書くのが望ましい）。

- 文字起こしのファイル名
- 相談のフォルダ名
- 実験の id
- 会話の ID の先頭 8 文字
- `hub/decisions.md`

リンクにしないで書いた記録のパスは、名前に「#」、空白、括弧があっても、その記録があれば「無いファイル」として出さない。それでも、リンクは `<…>` で囲み、「#」を `%23` にして書く。

## いつ動かすか

```
python -X utf8 .claude/skills/harness-record-links/scripts/record_links.py
python -X utf8 .claude/skills/harness-record-links/scripts/record_links.py --check   （書き込まず、切れたリンクと、相談の記録につながっていない文字起こしを数える）
```

- 会話が終わるときに、フックで自動で動く（`harness-session-archive` の後）。
- 記録の「関連」を書いた・直したら動かす。
- 統括が報告を受けたとき（`harness-dispatch` の 6）に動かす。
- 切れたリンク（無いファイル、無い印）が出たら、指している側の記録を直す。指している記録がほかの会話の持ち物（報告、作業の会話の要約など）でも、統括はリンクの先だけを直してよい。ほかは直さない（`CLAUDE.md` の「ファイルの持ち主」の例外）。
- 相談の記録につながっていない文字起こしが出たら、`harness-meeting-record` でつなぐ。文字起こしの道具を研究で置き換えたときに、つなぐ段が抜けても気づけるようにするため。相談ではないもの（一人で録ったメモ、指導教員から届いた文書など）は、文字起こしの冒頭の「相談の記録」の行を「なし」にする。
  - スクリプトがこの行で読むのは「なし」かどうかだけ。「なし」なら、この一覧に出さない。
  - つながっているとみなすのは、相談の記録がその文字起こしを指しているとき（相談の記録の「関連」などに書いたとき）だけ。文字起こしの冒頭の行に相談の名前を書いても、つながったことにはならない。

## コミット

- 自動の囲みと一覧だけの更新は、件名を `chore(links): …` にする。
- `Hub-Session:` の行は付けない（`Hub-Agent:` などの行は付ける）。会話の要約の「ハブのコミット」の一覧に載らないようにするため。
