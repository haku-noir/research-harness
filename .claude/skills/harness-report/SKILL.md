# ハブに報告する

作業セッションで使います。ハブの外のディレクトリにいる場合も、同じ手順を `<hub>/harness/roles/common.md` の「3. 報告」から読めます。`<hub>` は指示書に書いてあるハブのパスです。

## 手順

1. **自分の作業の id を確かめる。** 指示書の名前です。指示書が無い場合は、研究者にどの作業として報告するかを聞く。統括に新しい作業として登録してもらうなら、報告の「統括への提案」に書く。
2. **報告の節を足す。** `<hub>/hub/reports/<id>.md` の末尾に、`<hub>/harness/templates/report.md` の形で、日時の付いた節を足す。ファイルが無ければ、ひな形の見出しから作る。
   - **確かめたこと**と**確かめていないこと**は必ず分ける。確かめたことには、証跡のパスを付ける。
   - **決まったこと**には、だれが決めたかを書く（研究者・指導教員・自分が置いた値）。
   - **変えたもの**には、リポジトリ、ブランチ、コミットの短い ID、主なファイルを書く。未コミットなら、そう書く。
3. **用語集の候補を挙げる。** 新しく決まった用語、言い換え、固有名詞、誤認識しやすい語があれば、報告の「用語集に足すもの」に、どの表に入れるかと出典を付けて書く。言い換えを決めたときは、どの行を書き換えるかを書く。`<hub>/hub/glossary.md` は直接書き換えない（統括が反映する）。
4. **実験の記録を更新する。** 指示書が実験の id を示していれば、`<hub>/records/experiments/<id>/README.md` の該当の表（実装・実施・解析）を更新する。「関連」の欄に、自分の会話の要約へのリンクを足す。
5. **自分の会話の要約を書く。** `harness-session-archive` のスクリプトを動かし、自分の会話（環境変数 `CLAUDE_CODE_SESSION_ID`）の要約のファイルに、要約を書くか続きを足す（書き方は `harness-session-archive`）。報告の「決まったこと」は、要約の「決まったこと」にも書く。
6. **コミットする。** ハブのコミットの方針が「区切りごとにコミット」なら、変えたハブのファイルだけを名前で指定してコミットする。説明の最後に `Hub-Session: <環境変数 CLAUDE_CODE_SESSION_ID の値>` を付ける。
7. **最後のメッセージを書く。** 報告の要点（3〜6 行）と、報告ファイルのパスにする。研究者の答えを待っているなら、そのことを最初に書く。

## 書かないもの

統括が持つファイルには書きません。

- `hub/state.md`
- `hub/workstreams.md`
- `hub/decisions.md`
- `hub/briefs/`

変えてほしいことは、報告の「統括への提案」に書きます。
