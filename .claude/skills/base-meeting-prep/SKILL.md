# 相談の準備

統括のセッションで使います。

## 1. 前回を特定する

1. `records/meetings/` から、前回の相談の記録を探す。研究者が別の回を指定すれば、それに従う。読むのは次の三つ。
   - 見せたもの
   - 指導教員の反応
   - 決まったこと・宿題
2. 反応の記録（`chats/` の文字起こし、レビュー）を読み、指摘を一つずつ取り出す。
3. 前回の記録の末尾の「この記録を指しているもの（自動）」を見る。指摘に対応した作業（指示書・報告）、決定、会話が並んでいる。

## 2. それから何が進んだかを集める

前回の日付以降を集めます。`harness-progress-timeline` の材料を使います。

- **論旨**：版の変化と、その間のコミットの説明（`git log -- papers/<論文の id>/`）。主張・仮説・RQ がどう変わったか。
- **決定と方針転換**：その間の `hub/decisions.md` のコミット（`git log -p -- hub/decisions.md`）
- **作業**：完了したもの、進行中のもの（`hub/workstreams.md`、`hub/reports/`）
- **実装**：何ができるようになったか、検証で確かめたことと、実際の環境で未確認のこと
- **実験と解析**：実施した回、データ、解析と図（`records/experiments/`）。図はパスで示す。
- **試行**：何を確かめ、本流に入れたか・残したか・捨てたか

## 3. 準備のファイルを作る

`harness-meeting-record` の「1. 相談の記録を用意する」で、`records/meetings/<予定日>_<題>/README.md` を用意します。同じフォルダに `prep.md` を作り、`README.md` の「前回の指摘への対応」を先に埋めます（1 の 3 で見た、対応した作業から）。「関連」の欄には、この相談で扱う実験・決定へのリンクを書きます。

前回からの進みを集めるときは、`records/links.md` で前回の相談の記録から先をたどると早い。

`prep.md` の形：

```
# 相談の準備：YYYY-MM-DD

## 前回（YYYY-MM-DD）からの進み
- （論旨・実装・実験・解析・試行。要点を 5〜8 行）

## 前回の指摘への対応
| 前回の指摘（出典の節） | 対応 | どこに反映したか | 残り |

## 見せるもの
| もの | 版・ファイル | 見せる目的（何を判断してもらうか） |

## 聞くこと（影響の大きい順）
1. 問い：
   - 背景（なぜ指導教員の判断が要るか）：
   - 選択肢と、こちらの推奨：
   - 決まると何が進むか：

## 報告だけのこと
- （判断は要らないが、知っておいてもらうこと）
```

## 4. 聞くことの選び方

- **研究者だけで決められることは入れない。** 「聞くこと」は、指導教員の判断が要るものに絞る。例：
  - 論旨の方向
  - 指導教員の過去の発言どうしの食い違い
  - 用語の定義の採否
  - 実験の方針の選択
  - 範囲の線引き
- **答えやすい形にする。** 一つの問いに一つの判断。選択肢と推奨を付ける。
- **未決事項から拾う。** 論旨の正本の「未決事項」のうち、指導教員の確認が要ると書いたものを拾う。
- **数値は図と一緒に出す。** 実験や解析の結果は、図のパスと、確かめたこと・確かめていないことの区別を付ける。

## 5. 見せる資料

- 論旨の文書を見せるなら、確認用の資料を作る（`base-review-export` か、研究で置き換えたスキル）。
- 作ったものは、`harness-meeting-record` の「2. 見せたものを記録する」で記録する。

## 6. 研究者に渡す

- **渡すもの**：`prep.md` の要点（進み、対応、聞くこと）と、ファイルのパス。
- **統括が直すもの**：`hub/state.md` の「次の相談」を、予定日と `prep.md` の場所に直す。予定の日が変わったら、`harness-meeting-record` の「約束」の「相談の日が変わったら」に従い、フォルダの名前と一緒に、「次の相談」、`README.md` の題、`prep.md` の見出しの日付も直す。
- **相談の後**：文字起こしやレビューを `chats/` に置き（`base-transcript-fix` か、研究で置き換えたスキル）、`harness-meeting-record` で同じ相談の記録につなぐ。
