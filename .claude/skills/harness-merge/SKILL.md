# 試行を合流させるかを決める

統括のセッションで使います。決めるのは研究者です。統括は、判断の材料をそろえて推奨を示し、決まったことを記録します。

## 1. 材料をそろえる

1. `hub/reports/<id>.md` を読む。推奨と、その理由も読む。
2. 証跡を確かめる。差分、ログ、図、下書きなど、報告が示すものが実際にあるか。
3. 本流に入れると何が変わるかを、自分でも確かめる。

| 本流 | 確かめること |
|---|---|
| 論旨 | どの主張・仮説・未決が変わるか。新しい論点が入るなら、いまの論点と混ざらないか |
| 実装 | どのファイル・仕様が変わるか。他の作業のブランチと重ならないか |
| 実験の計画 | 条件・指標・予測が変わるか |

## 2. 研究者に示す

次のものを示します。

- **試行で確かめたこと**：結果と証跡
- **確かめていないこと**
- **選択肢**：それぞれで何が起きるか
  - 本流に入れる
  - 別に残す（今は入れないが、記録して後で見直す）
  - 捨てる
- **推奨**：理由と一緒に。報告の推奨と違うなら、なぜ違うか。

研究者が決めるまで、本流には何も入れません。

## 3. 決まったら

**本流に入れる**：

- 論旨：論旨の作業として切り出す（`harness-dispatch`）。小さな改訂なら、統括で `harness/roles/argument.md` に従って行う。版を上げ、コミットの説明のきっかけに「試行 `<id>`」と書く。
- 実装：ブランチのマージは、研究者の指示があるときだけ行う。指示が無ければ、コマンドを示すだけにする。

**別に残す**：試行のブランチや下書きは消さない。`hub/workstreams.md` の状態を「別に保持」にする。

**捨てる**：ブランチや下書きは、既定では消さない。作業の一覧の行は、4 のとおり消す。

- ハブの中のブランチは消さない（`CLAUDE.md` の「履歴を書き換えない」）。
- コードのリポジトリのブランチや、git の外の下書きを消すかは、研究者に確かめてから。

## 4. 記録する（どの場合も）

- `hub/decisions.md`：試行の結果で決まったことを、現在の決定として書く（または書き換える）。「捨てる」で終わり、残す決定が無ければ書かない。
- `hub/workstreams.md`：
  - 「別に保持」なら状態をそう直す。
  - 本流に入れた、または捨てたなら行を消す。
- `hub/state.md`：現在地が変わったら直す。
- コミットの説明に、試行 `<id>` の結論（入れる・残す・捨てる）、理由、決めた人を書く。これが履歴になる。
