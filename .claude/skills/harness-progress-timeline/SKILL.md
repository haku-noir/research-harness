# 進捗と方針転換を整理する

ハブの現在の文書には、現在の内容だけが書いてあります。経緯は履歴にあります。

- git のコミットの説明（前・理由・きっかけ）
- `records/`
- `hub/reports/`
- `chats/`

このスキルは、履歴から経緯を組み立てて示します。現在の文書は書き換えません。

## 1. 範囲と目的を確かめる

- 期間：全部、前回の相談から、など。
- 目的：
  - 流れの把握
  - ある決定の経緯（「なぜこう決めたか」）
  - 相談の準備（相談の準備のスキルから使われる）
  - 導入（`harness-install` から呼ばれる）
  - 発表の背景
- 出力：会話で示すだけ（既定）。残すように頼まれたら、`records/history/<期間>_<題>.md` に、履歴の記録として書く。現在の文書には書かない。

## 2. 材料を集める（信頼できる順）

1. **ハブの git の履歴**：コミットの説明に「前・理由・きっかけ」がある。最後の `Hub-Agent:` の行で、どの AI の作業かが分かる。

   ```
   git log --date=short --format='%ad %h %s%n%b' -- <ファイルやフォルダ>
   git log -p -- hub/decisions.md          （ある決定の変化を追う）
   git tag --sort=creatordate               （見せた版のタグ）
   ```

   取り込んだ git（`archive/…` のブランチ）がある場合、取り込みより前の経緯はそのブランチの履歴にある（`git log archive/<名前>/<ブランチ>`）。別の PC で複製したハブでは、そのブランチは `origin/archive/<名前>/<ブランチ>` としてだけあるので、`git log origin/archive/<名前>/<ブランチ>` で見る（`harness-install` の 3）。`hub/profile.md` の「取り込んだ履歴」を見る。

2. **ハブの記録**：
   - `records/meetings/*/README.md`
   - `records/experiments/*/README.md`
   - `records/history/`
   - `hub/reports/*.md`
3. **コードのリポジトリの git**：`hub/profile.md` と `hub/workstreams.md` に登録した場所。

   ```
   git -C <場所> log --all --format='%ad %h %d %s' --date=short
   ```

4. **`chats/` のファイル**：題と冒頭の日付。指導教員の発言が、どの日に入ったか。
5. **Claude Code の会話の履歴**：git に経緯が無い期間（導入より前など）に使う。研究者の発言を日付つきで取り出す。

   ```
   python -X utf8 .claude/skills/harness-progress-timeline/scripts/claude_history.py --list
   python -X utf8 .claude/skills/harness-progress-timeline/scripts/claude_history.py --project <作業ディレクトリ> --subdirs --since YYYY-MM-DD --out <git の外の一時ファイル>
   ```

   - `--project` には、そのとき Claude Code を開いていたディレクトリを指定する（`--list` が、記録のフォルダごとに実際の作業ディレクトリを出す）。`--subdirs` で、その下のフォルダやワークツリーで開いた会話も含める。
   - 分岐した会話の重複は除かれる。時刻は手元の時刻。
   - 研究者が打っていない入力（統括が作業の会話に送った起動の文など、ほかの会話・アプリからの入力）は除かれる。研究者の発言ではないため（承認と決定は研究者が言ったことだけ。`CLAUDE.md` の「承認と決定」）。
   - 出力には研究の中身がそのまま入るので、git の外（一時フォルダ）に書く。

## 3. 組み立てる

示し方は三つです。

1. **時期ごとの表**（初めに示す）

   | 時期 | 中心の作業 | 主な成果物 |
   |---|---|---|

   作業が切り替わったところで時期を区切る。区切りは、論旨と実装の行き来、発表、相談など。

2. **方針転換の一覧**

   | 日付 | 何が変わったか（前 → 後） | きっかけ | 影響 |
   |---|---|---|---|

   - きっかけは、指導教員のレビュー・相談・実験の結果・研究者の判断のどれか。ファイル名で示す。
   - 戻した変更（ある版を土台に戻した、など）も含める。

3. **日付ごとの詳細**（頼まれたとき）

   印（［論旨］［文献］［実装］［実験］［解析］［発表］［相談］［決定］［試行］）を付けて、日付ごとに並べる。

## 4. 書き方

- **事実と解釈を分ける。** 履歴から推した「なぜ」は、推定と書く。きっかけが分からないものは「不明」と書く。
- **過去の決定には時点を付ける。** 現在も有効かどうかを、現在の文書（`hub/decisions.md`、論旨の正本）と照らして書く。
- **研究と関係ない会話は外す。** 履歴に、研究と関係ない会話（別の企画の話、道具の設定）が混ざっていたら、外したことを一言書く。
- **残す前に確かめる。** `records/history/` に残す前に、時期ごとの表と方針転換の一覧を研究者に見せて、直してもらう。
