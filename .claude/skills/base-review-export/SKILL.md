# 確認用の資料を出力する（見本）

見せ方は、見せる時期や相手によって変わります。この見本は細かく決めず、使うたびに研究者に聞いて作ります。研究で作り方が決まってきたら、`hub/rules.md` に書くか、研究独自のスキルに置き換えてください（README の「研究に合わせて直す」）。

## 守ること

- **正本を書き換えない。** 見せたくないものを外すために、正本を直接削らない。出力は別のファイルにする。
- **出力は git の外に置く。** 既定は `papers/<論文の id>/export/`（`.gitignore` 済み）。作り直せるため。見せたものは、相談の記録に写して残す（下の 4）。
- **見せたものは記録する。** `harness-meeting-record` に渡す。この見本を置き換えても、この段は残す。

## 手順

1. **聞く。** `hub/rules.md` に決まりがあれば、聞かずにそれに従う。
   - 何を見せるか：どの文書の、どの部分か。どの版か。
   - 何を外すか：作業のメモ、未決事項、内部の印など。
   - 形：Markdown、PDF など。題、目次などの体裁。
   - 見せる相手と日：相談の記録に使う。
2. **作る。** 正本を読み、聞いた内容に沿って一つの資料にまとめる。冒頭に、元にした正本の版を書く。PDF にするなら、手元にある道具（ブラウザの印刷、pandoc など）を研究者と決める。
3. **通して読む。** 外すと言われたものが残っていないかを確かめる。残っていたら、出力を直すだけでなく、次から自動で外れるように正本の書き方（印など）を決めるかを研究者に聞く。決めたら `hub/rules.md` に書く。
4. **渡して記録する。**
   - 出力の場所を、この会話で研究者に伝える。ファイルを研究者に見せる道具があれば使ってよい。指導教員やほかの人、外部のサービスには送らない。指導教員やほかの人に見せるのは、研究者が自分で行う（`CLAUDE.md` の「ハブを公開しない」。この見本を置き換えても変わらない）。
   - `harness-meeting-record` の「2. 見せたものを記録する」に渡す。見せた資料を相談の記録に写すこと、「見せたもの」の記入、見せた版のタグは、そちらで行う。
5. **作り方を残す。** 同じ作り方を繰り返すようになったら、`hub/rules.md` に書くか、研究独自のスキルにすることを研究者に提案する。
