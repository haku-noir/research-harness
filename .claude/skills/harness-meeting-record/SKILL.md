# 相談の記録をつなぐ

相談の記録は、「何を見せ、指導教員が何と言い、何が決まり、どう対応したか」を一組にした履歴です。前回からの進みと、次に何を聞くかを組み立てる元になります。

材料（見せる資料、文字起こし、準備のまとめ）は、研究ごとのスキルが作ります。このスキルは、材料を相談の記録に置き、ほかの記録とつなぎます。材料を作るスキルを研究ごとに置き換えても、ここは変わりません。

## 約束

- **置き場所**：`records/meetings/<日付>_<題>/README.md`。ひな形は `harness/templates/meeting.md`（`hub/templates/meeting.md` があればそちら）。日付は相談の日。
- **相談の日が変わったら、フォルダの名前を直す。** 準備のときは予定の日で作るため。名前を直したら、`harness-record-links` の切れたリンクで、指している記録を見つけて直す。
- **一回の相談に一つのフォルダ。** 同じ日の同じ相手との話は一つにまとめる。どのフォルダに当たるか分からなければ、研究者に聞く。
- **書くのは統括。** 作業の会話で材料を作ったら、その会話は報告に書き、統括がこのスキルでつなぐ（`CLAUDE.md` のファイルの持ち主）。
- **決まったことは、研究者が確かめたものだけ。**

## 1. 相談の記録を用意する

1. `records/meetings/` から、その相談の記録を探す。準備のスキルが先に作っていれば、それを使う。
2. 無ければ、フォルダと `README.md` を作る。種類と相手を書く。
3. 「関連」の欄に、前回の相談の記録へのリンクを書く。

## 2. 見せたものを記録する

確認用の資料や発表資料ができたとき、または見せた後に行います。

- 見せた資料（PDF、スライド、図など）を、相談の記録のフォルダに写す。生成物でも、見せたものは記録なので git に入れる。大きすぎる、または秘密で写せないものは、場所だけ書く。
- 「見せたもの」の表に、もの、版とコミット、ファイルを書く。
- 論旨の版を見せたなら、見せた版に git のタグ（例：`<論文の id>/review-v<版>`）を付ける（論旨の手引き）。
- 見せる日が決まっていなければ、研究者に聞く。

## 3. 文字起こしをつなぐ

文字起こしが `chats/` に置かれたときに行います。

- **反応・レビュー**：「指導教員の反応・レビュー」に、文字起こしのファイル名と要点を書く。要点には、文字起こしの節を示す。
- **関連**：「関連」の欄に、文字起こしへの相対リンクを書く。
- **決定の候補**：発言のうち、指示・決定・方針の変更に当たりそうなものを、節を付けて一覧にし、研究者に示す。
  - 決まったかどうかは研究者が決める。
  - 研究者が確かめたものを、次の二つに書く。
    - 相談の記録の「決まったこと」（その時点の記録）
    - `hub/decisions.md`（現在の決定。前の決定があれば書き換え、前の内容はコミットの説明に書く。「会話」の欄に、決めた会話の要約へのリンクを書く）
- **論旨とのずれ**：いまの論旨とずれる発言があれば、どこがずれるかを短く示す。論旨には入れない。入れるかは別に判断する。
- **宿題・次に聞くこと**：出たものを書く。

## 4. 対応する作業とつなぐ

- 指導教員の指摘に対応する作業を切り出すときは、`harness-dispatch` の指示書の「関わる相談」に、この相談の記録と文字起こしを書く。作業の会話は、報告の「関連」にも書く。
- これで、相談の記録の末尾の「この記録を指しているもの（自動）」に、対応した作業・決定・会話が並ぶ。相談の記録に、対応を手で書き足す必要はない。
- 「前回の指摘への対応」の表は、次の相談の準備のときに、前回の記録の末尾から作る。

## 5. 仕上げる

1. `harness-record-links` を動かす。
   - 切れたリンクが出たら直す。
   - どの相談の記録にもつながっていない文字起こしが出たら、どの相談のものかを研究者に聞いて、3 を行う。相談ではないもの（一人で録ったメモ、指導教員から届いた文書など）なら、その文字起こしの冒頭の「相談の記録」の行を「なし」にする。
2. コミットする。説明は `CLAUDE.md` の「現在の文書と履歴」の形で書く。きっかけには、相談の記録と文字起こしのファイル名を書く。
