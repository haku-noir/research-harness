# 論旨の作業の手引き

論文ごとの論旨の正本（`<hub>/papers/<論文の id>/`）を詰めて更新する作業です。どの論文の作業かは指示書に書いてあります。統括のセッションで小さな改訂を行うときも、この手引きに従います。

議論の進め方は `<hub>/harness/base-rules.md`、書き方の決まりは `<hub>/hub/rules.md` に従います。書き方は研究や指導教員によって違うので、この手引きには置きません。

## 研究の全体像と、論文ごとの論旨

- **研究の全体像**（`<hub>/hub/research.md`）：論文をまたいで持ち続ける、研究全体の問い、位置づけ、これまでに分かったこと、まだ分かっていないこと。
- **論文ごとの論旨**（`<hub>/papers/<論文の id>/argument.md`）：その論文で、全体のどの問いを論点にし、どう論旨を組むか。論文を書くたびに組み直す。
- 論旨の作業は、研究の全体像を読んでから始める。研究の全体像を直すべきこと（新しく分かったこと、問いの変化）に気づいたら、論旨には書かず、統括への提案として報告する。研究者が決めてから、統括が書く。
- **新しい論文を始めるとき**：統括が研究者と、扱う問い、論文の種類、文書の組を決め、`papers/<論文の id>/` を作る（`harness/templates/argument.md` から）。統括は、`hub/research.md` の「論文」の表に 1 行足す。前の論文の論旨から使える部分は、写してよい（論文ごとに読める形にするため）。
- **書き終えた論文**（提出・発表が済んだもの）の論旨は、読み出しのみにする。分かったことは、研究者が決めて、研究の全体像の「これまでに分かったこと」に書く。統括は、`hub/research.md` の「論文」の表の「状態」を直す。

## 正本の約束

- **論旨はハブに置く。** 本文の原稿は、共著のリポジトリなどハブの外に置いてもよい（場所は論旨の冒頭の「本文の原稿」）。外の原稿は文書の組に入れず（版の番号を合わせない）、論旨と食い違ったら論旨が正しい。外の原稿には、ハブの中身（未決事項、文字起こし、指導教員の未発表の考え）を書かない。
- **論文ごとに正本は一つ。** その論文の論旨は `papers/<論文の id>/argument.md` が正本。骨子や本文の仮組を置く場合は、正本に従う。食い違ったら正本が正しい。
- **同じ版にする。** 正本を変えたら、文書の組（正本の冒頭に書く）の文書も同じ変更の中で合わせる。合わせる必要が無いなら、無いことを確かめる。組の文書の冒頭の「版」は同じ番号にする。
- **現在の論旨だけを書く。** 論旨が変わったら、古い記述を残さずに書き換える。次のものは正本に書かない。
  - 「v〇で改めた」「〇〇まで」「取り下げた」のような注記
  - 前の名前
  - 決定の経緯
  - 変更履歴の節
- **経緯はコミットの説明に書く。** 前の記述、理由、きっかけを書く。きっかけは `chats/` や `records/` のファイル名で示す（形は `CLAUDE.md` の「現在の文書と履歴」）。
- **見せた版にタグを付ける。** 指導教員に見せた版には、git のタグ（例：`<論文の id>/review-v<版>`）を付ける。後から「何を見せたか」を取り出せるようにするため（`harness-meeting-record`）。
- **大きく変わるならブランチを切る。** ハブの中では、ワークツリーで切る（下の「大きな改訂のブランチ」）。マージは研究者の指示があるときだけ行う。指示が無ければ、マージのコマンドを示すだけにする。
- **根拠の状態が分かるようにする。** 各主張が何に支えられているか（指導教員の発言、原典を読んだ文献、読んでいない文献、確かめていない解釈）を、読み手が区別できるように書く。印の付け方は研究ごとに決め、`hub/rules.md` に書く。
- **`hub/decisions.md` の決定を入れたら、報告に書く。** `hub/decisions.md` にある論旨の中身の決定（相談の記録から統括が書いたものなど）を正本に入れたら、どの項目を入れたかを報告に書く。統括が、その項目を `hub/decisions.md` から消す（以後は論旨の正本に置く）。統括のセッションで小さな改訂として入れたときは、統括がそのまま消す。
- **未決事項は残す。** 決まっていないことは、正本の「未決事項」に ID を付けて残す。決まったら、未決事項から消し、本文の該当箇所を決定の内容に書き換える。だれが決めたかは本文の出典で示し、いつ決めたかはコミットの説明に書く。

## 大きな改訂のブランチ

ハブの作業コピーのブランチは切り替えない（`CLAUDE.md` の「ファイルの持ち主」）。切り替えると、統括の作業まで別のブランチに載るため。ブランチは、ハブのワークツリーで切る。

1. **統括が、切り出すときに作る。** ハブのフォルダで `git worktree add .claude/worktrees/<名前> -b <ブランチ>` を行い、指示書の「作業の場所」に、そのパスとブランチを書く。
2. **作業の会話は、論旨をそのワークツリーで直してコミットする。** 報告、自分の会話の要約、実験の記録は、元のハブのフォルダ（`<hub>`）に、ハブのいまのブランチで書いてコミットする。スクリプトは元のハブのもの（`<hub>/.claude/skills/…`）で動かす。
3. **マージは、研究者の指示があるときだけ。** 統括が、元のハブのフォルダで次を行う。指示が無ければ、このコマンドを示すだけにする。

   ```
   git merge --no-ff --no-commit <ブランチ>
   git commit -F <説明を書いたファイル>
   ```

   マージのコミットも、説明はハブのコミットの形（前・理由・きっかけと `Hub-Agent:` などの行。`CLAUDE.md` の「現在の文書と履歴」）で書く。`--no-commit` を付けずにマージすると、git が決まった文の説明でコミットしてしまうため。きっかけには研究者の指示を書く。
4. **マージした後**：統括が `hub/state.md` の論旨の版を直し、`git worktree remove .claude/worktrees/<名前>` でワークツリーを外す。ブランチは消さない（ハブの中のブランチは消さない。`CLAUDE.md` の「履歴を書き換えない」）。

## 新しい指導教員の発言

- **すぐ論旨に入れない。** まず `chats/` に記録され、相談の記録につながっているかを確かめる。次に、いまの論旨とどこがずれるか、入れると何が変わるかを示す。入れるかは研究者が決める。
- **書き方の決まりが出たら、報告する。** 指導教員のレビューで書き方の決まりが出たら、統括への提案として報告する。統括が研究者に確かめて `hub/rules.md` に足す。
