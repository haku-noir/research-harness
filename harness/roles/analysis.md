# 解析の作業の手引き

実験や予備実験のデータを解析し、図と数値を出す作業です。

## 置き場所

- **データは git に入れない。** 置き場所は `hub/profile.md` に書いた場所か、指示書が示す場所。実験の記録には、所在だけを書く。
- **解析のスクリプトは、git で管理する場所に置く。** 解析用のリポジトリか、指示書が示すディレクトリ。図や数値を出したら、そのときのコミットを記録する。スクリプトを通さずに直した図は使わない。直すならスクリプトを直す。
- **図は保存して記録する。** 図のファイルは、実験の記録から参照できる場所に保存する。既定は `<hub>/records/experiments/<id>/figures/`。

## 記録（`<hub>/records/experiments/<id>/README.md` の「解析」）

解析ごとに節を足します。

- **目的**：前もって決めた解析か、探索的な解析か。
- **スクリプト**：パスとコミット。
- **入力のデータ**：どの実施の、どのファイルか。除外したものと、その理由。
- **図**：パスと、図ごとに 1 行の説明（何を横軸・縦軸にし、何を比べたか）。
- **結果**：数値、N、ばらつき。
- **解釈**：結果（事実）と分けて書く。論旨のどの予測と合う・合わないか。
- **関連**：実験の記録の「関連」の欄に、解析した会話（自分の会話）の要約へのリンクを足す。この実験を見せた相談は、実験の記録の末尾の「この記録を指しているもの（自動）」に自動で並ぶ（相談の記録の「関連」から）ので、書かなくてよい。

## 書き方

- **解析の方針を先に決める。** 前もって決めた解析を先に行い、探索的な解析は分けて示す。
- **方針が決まっていないときは聞く。** 指標の式、除外の基準、統計の方法が決まっていなければ、推測で選ばずに聞く。案は出してよい。
- **言えることの範囲で書く。** 予備実験の少ない N の結果を、本実験の結論のように書かない。
