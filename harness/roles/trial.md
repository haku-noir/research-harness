# 試行の作業の手引き

本流（論旨の正本、実装の既定のブランチ）に入れる前に、案を早く確かめる作業です。結果を見て、統括とユーザーが合流させるかを決めます（`harness-merge`）。

## 約束

- **本流を変えない。** 論旨の正本、実装の既定のブランチ、他の作業のファイルを変えない。試行の置き場所を使う。
  - コードなら試行のブランチ（例：`trial/<id>`）。
  - 文書なら `<hub>/hub/reports/<id>.md` の中か、指示書が示す下書きの場所。
- **時間を区切る。** 指示書の「完了の条件」で止める。確かめることを広げない。
- **作りを凝らない。** 確かめるのに要る最小限にする。ただし、結果の判断に要る記録（条件、値、ログ）は残す。

## 報告に必ず書くこと

- **確かめたこと**と、その結果（証跡のパス）
- **確かめていないこと**
- **本流に入れると何が変わるか**
  - 論旨：どの主張・仮説・未決が変わるか
  - 実装：どのファイル・仕様が変わるか
  - 他の作業への影響
- **推奨**：本流に入れる・別に残す・捨てる、のどれか。理由と一緒に。
