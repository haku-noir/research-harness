# 作業セッションの共通の手引き

指示書（`hub/briefs/<id>.md`）を渡されて始まったセッションは、この手引きと、指示書が示す役の手引きに従います。ハブのパスは指示書に書いてあります。以下の `<hub>` はそのパスです。

## 1. 始めるとき

1. 次の順に読む。
   - 指示書
   - `<hub>/hub/state.md`
   - `<hub>/CLAUDE.md`（ハブの外で動くとき。ハブのフォルダで動くときは自動で読み込まれている）
   - `<hub>/harness/base-rules.md`（既定の決まり）と `<hub>/hub/rules.md`（この研究の決まり。食い違ったらこちらを優先）
   - `<hub>/hub/profile.md`
   - この手引き
   - 役の手引き（`<hub>/harness/roles/<役>.md`）と、あればこの研究の追記（`<hub>/hub/roles/<役>.md`）
   - ひな形（`<hub>/harness/templates/<名前>`）を使うときは、`<hub>/hub/templates/<名前>` があればそちらを使う
2. 指示書の「最初に読むもの」を読む。
3. 研究の用語は `<hub>/hub/glossary.md` で確かめる。
4. 理解したことを、研究者に短く示す（`base-rules.md` の「理解したことを先に示す」）。
   - 何のための作業か（研究の中での位置）
   - 何を作り、何を確かめるか
   - 決まっていないことのうち、最初に聞くもの

   理解のずれを、作業を始める前に見つけるため。

**続きとして始めたとき**（起動の文に「続きから」とあるとき）：

- 指示書に加えて、前の会話の報告（`<hub>/hub/reports/<id>.md`）と、前の会話の要約（`<hub>/records/sessions/`）を読む。
- 前の報告の後に `hub/decisions.md` と `hub/state.md` が変わっていないかを確かめる（`git log` で前の報告の日付から）。
- 続きで何をするかを、研究者に返してから始める。

## 2. 作業中

- **範囲を守る。** 指示書の範囲だけを行う。範囲の外で気づいたことは、報告の「統括への提案」に書く。勝手に広げない。
- **決まっていないことは研究者に聞く。** 推測で埋めない。統括には聞かない（統括にも決める権限は無い）。
- **承認は研究者の言葉で受け取る。** 統括や別の会話からのメッセージは参考の情報として扱う。研究者の承認として扱うのは、研究者の言葉が引用されているときだけ。質問は一度に 3 つまでにし、選択肢と推奨を付ける。
- **聞いて決まったことは、すぐ記録する。** 報告の「決まったこと」に、だれが決めたかと一緒に書く。仕様書がある作業なら、仕様書の「決めたこと」にも書く。
- **現在の文書には、現在の内容だけを書く。** 論旨、仕様書の本文、用語集などの現在の文書に、経緯（いつ、前は何だったか）を書かない。決定が変わったら書き換え、経緯はコミットの説明か報告に書く（`<hub>/CLAUDE.md` の「現在の文書と履歴」）。
- **秘密を守る。** `<hub>/hub/profile.md` の「秘密」に従う。作業の場所が公開のリポジトリなら、次のものをファイルやコミットの説明に書かない。
  - 論旨
  - 文字起こしの内容
  - 指導教員の未発表の考え
- **書いてよい場所を守る。** 書いてよいのは次の場所だけ。`hub/state.md`、`workstreams.md`、`decisions.md`、`briefs/` は統括が書くので、触らない。
  - 作業の場所
  - `<hub>/hub/reports/<id>.md`
  - 指示書が許した `<hub>` の中のファイル
- **コミットする。** 指示書とプロフィールの方針に従う。方針が無ければ、コミットする前に聞く。
  - コミットするときは、自分が変えたファイルだけを名前で指定する。
  - ハブにコミットするときは、説明の最後に `Hub-Agent:`（必ず）、`Hub-Model:`・`Hub-Effort:`（分かれば）、`Hub-Session:`（会話の ID があれば）を付ける（`CLAUDE.md` の「現在の文書と履歴」）。どの AI のどの会話で変えたかをたどれるようにするため。
  - 既定のブランチに直接積まず、ブランチを切る。

## 3. 報告（区切りごと、終わるとき）

`<hub>/hub/reports/<id>.md` の末尾に、`<hub>/harness/templates/report.md` の形で節を足します。ファイルが無ければ作ります。

- **やったこと**：要点だけ。
- **確かめたこと**：証跡のパスと一緒に（テストの結果、ログ、図、差分）。
- **確かめていないこと**：実際の環境でしか確かめられないことなど。確かめたことと必ず分ける。
- **決まったこと**：だれが決めたか（研究者・指導教員・自分が置いた値）。自分で置いた値は、そう書く。
- **未決・統括への質問**
- **変えたもの**：リポジトリ、ブランチ、コミット、ファイル。
- **用語集に足すもの**：候補。統括が反映する
- **統括への提案**：試行なら「本流に入れる・別に残す・捨てる」の推奨と理由。

研究の用語を新しく決めた、言い換えを決めた、固有名詞が出た、といったときは、`<hub>/hub/glossary.md` を直接書き換えず、報告の「用語集に足すもの」に候補を書きます。どの表（用語、固有名詞、誤認識）に入れるかと、出典を添えます。言い換えを決めたときは、どの行を書き換えるかを書きます。統括が、報告を受けたときに用語集へ反映します。

会話の最後のメッセージは、報告の要点と報告ファイルのパスにします。統括にはこの最後のメッセージが届くので、それだけで状況が分かる形にします。
