# 作業セッションの共通の手引き

指示書（`hub/briefs/<id>.md`）を渡されて始まったセッションは、この手引きと、指示書が示す役の手引きに従います。ハブのパスは指示書に書いてあります。以下の `<hub>` はそのパスです。

## 1. 始めるとき

1. 次の順に読む。
   - 指示書
   - `<hub>/hub/state.md`
   - `<hub>/CLAUDE.md`（ハブの外で動くとき。ハブのフォルダで動くときは自動で読み込まれている）
   - `<hub>/harness/base-rules.md`（既定の決まり）と `<hub>/hub/rules.md`（この研究の決まり。食い違ったらこちらを優先）
   - `<hub>/hub/profile.md`
   - この手引き
   - 役の手引き（`<hub>/harness/roles/<役>.md`）と、あればこの研究の追記（`<hub>/hub/roles/<役>.md`）
   - ひな形（`<hub>/harness/templates/<名前>`）を使うときは、`<hub>/hub/templates/<名前>` があればそちらを使う
2. 指示書の「最初に読むもの」を読む。
3. 研究の用語は `<hub>/hub/glossary.md` で確かめる。
4. 理解したことを、研究者に短く示す（`base-rules.md` の「理解したことを先に示す」）。
   - 何のための作業か（研究の中での位置）
   - 何を作り、何を確かめるか
   - 決まっていないことのうち、最初に聞くもの

   理解のずれを、作業を始める前に見つけるため。

**続きとして始めたとき**（起動の文に「続きから」とあるとき）：

- 指示書に加えて、前の会話の報告（`<hub>/hub/reports/<id>.md`）と、前の会話の要約（`<hub>/records/sessions/`）を読む。
- 前の報告の後に `hub/decisions.md` と `hub/state.md` が変わっていないかを確かめる（`git log` で前の報告の日付から）。
- 続きで何をするかを、研究者に返してから始める。

## 2. 作業中

- **範囲を守る。** 指示書の範囲だけを行う。範囲の外で気づいたことは、報告の「統括への提案」に書く。勝手に広げない。
- **決まっていないことは研究者に聞き、承認は研究者の言葉で受け取る**（`<hub>/CLAUDE.md` の「承認と決定」）。質問は一度に 3 つまでにし、選択肢と推奨を付ける。
- **聞いて決まったことは、すぐ記録する。** 報告の「決まったこと」に、だれが決めたかと一緒に書く。仕様書がある作業なら、仕様書の「決めたこと」にも書く。
- **現在の文書には、現在の内容だけを書く。** 仕様書の本文も同じ（`<hub>/CLAUDE.md` の「現在の文書と履歴」）。
- **秘密を守る。** `<hub>/hub/profile.md` の「秘密」に従う。作業の場所が公開のリポジトリなら、ハブの中身をファイルにもコミットの説明にも書かない（`<hub>/CLAUDE.md` の「ハブを公開しない」）。
- **書いてよい場所を守る。** 書いてよいのは次の場所だけ。`hub/state.md`、`workstreams.md`、`decisions.md`、`briefs/` は統括が書くので、触らない。
  - 作業の場所
  - `<hub>/hub/reports/<id>.md`
  - 指示書が許した `<hub>` の中のファイル
- **コミットする。** 指示書とプロフィールの方針に従う。方針が無ければ、コミットする前に聞く。
  - 自分が変えたファイルだけを名前で指定する。
  - ハブにコミットするときの説明の形と最後の行（`Hub-Agent:` など）は、`<hub>/CLAUDE.md` の「現在の文書と履歴」。
  - 既定のブランチに直接積まず、ブランチを切る。

## 3. 報告（区切りごと、終わるとき）

報告の手順の全体です。ハブの外で動く会話には、ハブのスキル（`harness-report`）が読み込まれないので、ここに置きます。

1. **報告の節を足す。** `<hub>/hub/reports/<id>.md` の末尾に、`<hub>/harness/templates/report.md` の形で、日時の付いた節を足す。ファイルが無ければ作る。指示書が無ければ、どの作業として報告するかを研究者に聞く。
   - **確かめたこと**と**確かめていないこと**（実際の環境でしか確かめられないことなど）は必ず分ける。確かめたことには、証跡のパス（テストの結果、ログ、図、差分）を付ける。
   - **決まったこと**には、だれが決めたか（研究者・指導教員・自分が置いた値）を書く。
   - **変えたもの**には、リポジトリ、ブランチ、コミットの短い ID、主なファイルを書く。未コミットなら、そう書く。
   - **用語集に足すもの**：研究の用語を新しく決めた、言い換えを決めた、固有名詞が出た、といったときは、`<hub>/hub/glossary.md` を直接書き換えず、ここに候補を書く。どの表（用語、固有名詞、誤認識）に入れるかと出典を添え、言い換えならどの行を書き換えるかを書く。統括が反映する。
   - **統括への提案**：範囲の外で気づいたこと。試行なら「本流に入れる・別に残す・捨てる」の推奨と理由。
2. **実験の記録を更新する。** 指示書が実験の id を示していれば、`<hub>/records/experiments/<id>/README.md` の該当の表（実装・実施・解析）を更新し、「関連」の欄に自分の会話の要約へのリンクを足す。
3. **自分の会話の要約を書く。** `harness-session-archive` のスクリプトを動かし、自分の会話の要約のファイルに、要約を書くか続きを足す（書き方は `<hub>/.claude/skills/harness-session-archive/SKILL.md`）。報告の「決まったこと」は、要約の「決まったこと」にも書く。Claude Code 以外の AI は、その AI の読み替えに従う。
4. **コミットする。** 2 の「コミットする」に従う。
5. **最後のメッセージを書く。** 報告の要点（3〜6 行）と、報告ファイルのパスにする。研究者の答えを待っているなら、そのことを最初に書く。統括にはこの最後のメッセージが届くので、それだけで状況が分かる形にする。
