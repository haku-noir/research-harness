# Claude Code 以外の AI で使うとき（導入のとき・初めて使われたときに読む）

このひな形は、Claude Code で使う前提で書いた研究の進め方です。中身は Markdown の手順とファイルの約束なので、ほかの AI でも使えます。

このファイルは、ほかの AI が**導入のとき、または初めて作業の会話として使われたときに一度だけ**読むものです。読んだ AI は、自分の機能に合わせた読み替えを作り、以後はその読み替えに従います。毎回の会話でこのファイルを読む必要はありません。

## 1. 変えないもの

読み替えるのは道具の使い方だけです。次のものは、どの AI でも同じに守ります。

- **`CLAUDE.md` の約束**：承認と決定、ハブを公開しないこと、現在の文書と履歴（コミットの説明、履歴を書き換えないこと、日付の書き方を含む）、ファイルの持ち主、記録どうしのリンク。名前に Claude と付いていても、どの AI にも当てはまる約束として読む。
- **指示書と報告の形**（`harness/templates/brief.md`、`report.md`）：会話をまたぐ文脈の受け渡しは、この二つに頼っている。
- **push の守り**（`harness/hooks/pre-push`、`INSTALL.md` の 1-3）：git の段で働くので、どの AI でも効く。
- **秘密の扱い**（README の「秘密の扱い」、`hub/profile.md` の「秘密」）

## 2. 読み替えるもの

| このハーネスでの仕組み | Claude Code での動き | ほかの AI での読み替えの例 |
|---|---|---|
| 約束の読み込み（`CLAUDE.md` と、その中の `@hub/state.md` などの行） | 会話の始めに自動で読み込まれる | 会話の始めに、`CLAUDE.md` と `@` の行が指すファイルを読む |
| スキル（`.claude/skills/<名前>/SKILL.md`） | 頼まれた内容に合うスキルが選ばれる | 頼まれた内容に合う `SKILL.md` を読み、その手順に従う。各 `SKILL.md` の冒頭の説明文（`description`）で選ぶ |
| 作業の会話の起動（`harness-dispatch` の 5） | `harness/claude-code-notes.md` | 新しい会話やエージェントを作業の場所で開き、起動の文を送る。統括から開けなければ、研究者に開いてもらう |
| 作業の会話が終わったことを知る | 知らせが届く（デスクトップ版） | 研究者が統括に「終わった」と伝える |
| 会話の終わりのフック（`.claude/settings.json`） | 会話の記録と、記録どうしのリンクのスクリプトが自動で動く | 動かない。記録を書いた後に、リンクのスクリプトを手で動かす |
| 記録どうしのリンク（`harness-record-links` のスクリプト） | フックと手で動く | そのまま動く（ファイルだけを読む）。`python -X utf8 .claude/skills/harness-record-links/scripts/record_links.py` |
| 会話の記録（`harness-session-archive` のスクリプト） | Claude Code の会話の履歴を写し、要約のひな形を作る | 動かない。その AI が会話の終わりに、`harness/templates/session-summary.md` の形で要約を書く。ファイル名は `records/sessions/<開始日>_<8 桁の 16 進数>.md`（リンクのスクリプトがこの形で探すので、8 桁は会話ごとに決める）。会話の書き出しを残すなら、git の外の `records/sessions/raw/` に置く |
| 統括が始めるときの、要約が要る会話の確認（`--pending`） | スクリプトが一覧を出す | 行わない。要約の無い会話が無いかを研究者に聞く |
| 進捗の整理の、会話の履歴の取り出し（`harness-progress-timeline` のスクリプト） | Claude Code の会話の履歴を読む | 動かない。git の履歴と `records/` だけで組み立てる |
| コミットの説明の `Hub-Agent:` などの行 | `Hub-Agent: claude-code`、モデル、エフォート、会話の ID を付ける | `Hub-Agent:` に自分の名前を必ず付ける。モデルとエフォートは分かれば付ける。会話の ID のようなもの（セッションの ID など）があれば `Hub-Session:` に書く |
| 見本のスキルを隠す設定（`.claude/settings.local.json` の `skillOverrides`） | 置き換えた見本のスキルを隠す | 無い。`hub/rules.md` に書かれた、置き換えたスキルを使う |
| 道具の名前（`AskUserQuestion`、`start_session` など） | Claude Code の道具 | その AI の同等の機能。無ければ文章で聞く |
| コードのリポジトリとつなぐファイル（`CLAUDE.local.md`。`harness-install` の 6） | Claude Code が作業ディレクトリで自動で読む | その AI が作業ディレクトリで自動で読むファイルに、同じ中身を書く。公開のリポジトリなら、git に入らない形で置く（`.git/info/exclude`） |

## 3. 読み替えを作る（導入のとき）

`INSTALL.md` と `harness-install` の手順を進めながら、次を行います。

1. **2 の表を、自分の機能で一つずつ読み替える。** できないこと（自動で動かせない、別の会話を開けない）は、研究者が手で行う手順にする。
2. **読み替えを、自分が会話のたびに自動で読む場所に書く。**
   - 自分のファイル（例：Gemini CLI の `GEMINI.md`、Cursor の `.cursor/rules/`）を自動で読むなら、そこに書く。新しく作るファイルなので、研究の層に入る。
   - `AGENTS.md` を自動で読むなら、`AGENTS.md` は書き換えず（ひな形の持ち物）、研究の層に自分のファイルを作って書く（例：`hub/codex.md`）。`AGENTS.md` から `hub/profile.md` の「使う AI」の表を経てたどれる。
   - 書く中身：会話の始めに読むもの（`CLAUDE.md` と、その `@` の行が指すファイル）、2 の表の読み替え、できないことを研究者がどう補うか。
3. **場所を `hub/profile.md` の「使う AI」の表に書く。** 研究者や、ほかの道具で開いた人が見つけられるようにするため。
4. **研究者に見せて確かめる。** 読み替えで、研究者の手が増えるところ（会話を開く、終わったと伝える、要約を頼む）を、はっきり示す。

## 4. 初めて作業の会話として使われたとき

ハブをほかの AI で導入した後に、別の AI を作業の会話やレビューに使うことがあります（例：統括は Claude Code、実装だけ Codex）。

1. **表にあるかを確かめる。** `hub/profile.md` の「使う AI」の表に自分が無ければ、研究者の許可がまだ無い。作業を始めずに、研究者に確かめてもらう（`CLAUDE.md` の「ハブを公開しない」）。研究者が許可したら、許可を受けた会話の AI が表に 1 行足す。
2. **読み替えを作る。** 3 と同じ手順で、自分の読み替えを作り、場所を表に書く。作業の会話として使われるだけなら、読み替えは作業の会話に要るもの（指示書と報告、共通の手引き、コミットの説明）に絞ってよい。
3. **受け渡しに困るときは、そのときに決める。** ハブに書けない設定で動いているなど、指示書・報告の受け渡しがそのままではできないときは、統括とその AI の間で、そのときに受け渡し方を決める。決めたことは研究者に確かめ、読み替えに書く。

## 5. 研究に合わせて直すとき

ひな形の層（`CLAUDE.md`、`AGENTS.md`、`harness/`、`.claude/skills/harness-*`、`.claude/skills/base-*`）は書き換えず、研究の層で合わせます（`CLAUDE.md` の「スキルとひな形の層」、README の「研究に合わせて直す」）。読み替えのファイルも研究の層です。
