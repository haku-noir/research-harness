# 研究ハーネス（研究ハブのひな形）

一つの研究の論旨、文献、実装、解析、発表を、複数の Claude Code のセッションで分担するためのひな形です。セッションどうしは、文脈をファイルで共有します。

## 何が楽になるか

- **文脈の受け渡し**：実装や解析を別のセッションや別のディレクトリで進めるとき、「何の実験で、論旨のどこを確かめるためか」を毎回説明しなくてよくなります。作業セッションは、ハブの「現在地」と自分宛ての「指示書」を自分で読みます。
- **話が混ざらない**：統括役のセッションが作業を切り出し、報告を受けて記録します。論旨の議論と実装の相談が一つのセッションで混ざりません。
- **試してから決める**：気になる案は「試行」として別に確かめ、結果を見てから本流に入れるかを決められます。
- **相談の準備**：指導教員との相談の記録が、日付つきで残ります。記録するのは、見せたもの、レビュー、決まったこと、実装、実験のデータ、解析と図です。次の相談の前に「前回から何が進み、何を聞くべきか」をすぐまとめられます。
- **文字起こしの修正**：会話の文字起こしを、研究の用語集を参照して直します。用語集は、どの会話からも候補を出し、統括がまとめて育てます。

## 導入

Claude Code に、このリポジトリの URL を貼って、次のように言うだけです。

> https://github.com/haku-noir/research-harness これを導入したいです

Claude が [INSTALL.md](INSTALL.md) に従い、次のことを質問しながら進めます。

- ハブの置き場所
- 新しい研究か、進行中の研究か
- 既存の資料の場所
- 公開範囲

導入は 2 段です。段 1 で骨組み（置き場所、push の守り、プロフィール、現在地）を一つの会話で作ります。進行中の研究なら、段 2 で既存の資料を種類ごとに一つずつ取り込みます。段 2 は作業の一覧に項目として載るので、会話を分けても続きから進められます。

進行中の研究では、既存の文書、文字起こし、コード、Claude Code の会話の履歴から、現在地・決定・用語集と、導入前の経緯を組み立てます。元の資料は、許可なく動かしたり書き換えたりしません。

## 導入した後の使い方

ハブのフォルダで Claude Code を開きます。そのセッションが**統括役**です。

研究の進め方の全体（論旨の流れ、実装と実験の流れ、試行）は [harness/flow.md](harness/flow.md) にあります。

| 頼み方の例 | 使うスキル |
|---|---|
| 「予備実験の実装を別セッションで進めたい」「解析のセッションを作って」「ゼミ資料を別で作りたい」 | `harness-dispatch` |
| 「これ、本流に入れる前にさくっと確かめたい」 | `harness-dispatch`（試行）→ `harness-merge` |
| （作業セッションで）「ここまでを報告して」 | `harness-report` |
| 「この文字起こしを修正して」（生の文字起こしを貼る） | `base-transcript-fix` |
| 「日付ごとの進捗を見せて」「いつ方針が変わった？」 | `harness-progress-timeline` |
| 「予備実験に関係するものを全部」「この文字起こしを使っている決定は？」 | `harness-record-links`（`records/links.md` と各記録の末尾を作り直す） |
| 「会話の要約を書いて」「この決定はどの会話で決めた？」 | `harness-session-archive`（生の記録はハブの会話が終わるときに自動で写る。要約は Claude が書く） |
| 「新しい論文を書き始めたい」 | 統括（論旨の手引きの「新しい論文を始めるとき」） |
| 「次の相談の準備をしたい」「前回から何が進んだ？」 | `base-meeting-prep` |
| 「見せたものを記録して」「この文字起こしを相談につないで」 | `harness-meeting-record`（文字起こし・準備・確認用の資料のスキルの後にも使う） |
| 「教授に見せる資料を作って」 | `base-review-export`（見本。見せ方は使うたびに聞く） |
| 「既存の資料をハブに取り込みたい」 | `harness-install` |

## 構成

```
（ひな形の仕組み：更新を取り込む部分）
CLAUDE.md                 全セッション共通の約束
AGENTS.md                 Claude Code 以外の AI の入口（数行。導入と読み替えへの案内）
INSTALL.md                導入の手順（Claude が従う）
.claude/skills/harness-*  仕組みのスキル（研究ごとに変えない）
.claude/skills/base-*     見本のスキル（各研究で置き換える前提）
harness/base-rules.md     既定の決まり（研究ごとに hub/rules.md で上書きできる）
harness/flow.md           研究の進め方の全体
harness/claude-code-notes.md  Claude Code のアプリ（デスクトップ版・CLI）ごとの操作の補足
harness/other-ai.md       Claude Code 以外の AI で導入するときに読む、読み替えの材料
harness/roles/            統括の手引きと、作業の種類ごとの手引き（統括と作業の会話が読む）
harness/templates/        記録のひな形

（導入で作る：各自の研究の中身）
hub/state.md              現在地 1 ページ。全セッションが最初に読む
hub/profile.md            研究者・指導教員・場所・公開範囲
hub/rules.md              この研究の決まり（既定への追加と上書き）
hub/roles/  hub/templates/  手引きへの追記、ひな形の差し替え（必要なときだけ）
.claude/skills/<名前>     研究独自のスキル（頭文字の無い名前。必要なときだけ）
hub/glossary.md           用語、固有名詞、文字起こしの誤認識の表
hub/workstreams.md        作業の一覧
hub/briefs/  hub/reports/ 作業セッションへの指示書と、その報告
hub/decisions.md          いま有効な決定
hub/research.md           研究の全体像（論文をまたいで持ち続ける）
papers/<論文の id>/       論文ごとの論旨（論旨、骨子、本文の仮組など）
chats/                    修正済みの文字起こし、コメント、レビュー
records/meetings/         相談ごとの「見せたもの＋レビュー＋決まったこと」
records/experiments/      実験ごとの目的、実装の版、データの所在、解析と図
records/history/          導入前の経緯など、履歴の記録
records/sessions/         Claude Code の会話の要約（生の記録への参照つき。生の記録は git の外）
records/links.md          記録どうしのリンクの一覧（自動）
literature/index.md       文献の参照の一覧（原文は git に入れない）
slides/                   発表資料
```

コードやデータは、今までどおり別のリポジトリや別のフォルダに置きます。ハブは場所を記録し、作業セッションをそこで動かします。

## 研究に合わせて直す

このひな形は土台です。各研究は、ひな形の層を書き換えずに、研究の層で合わせます。研究で変えたものが研究の層に集まり、何を変えたかが一目で分かります。

### ひな形のスキルは 2 種類

| 種類 | スキル | 研究ごとに |
|---|---|---|
| 仕組み（`harness-`） | `harness-install`、`harness-dispatch`、`harness-report`、`harness-merge`、`harness-session-archive`、`harness-record-links`、`harness-progress-timeline`、`harness-meeting-record` | 変えない。写さない、`off` にしない |
| 見本（`base-`） | `base-transcript-fix`、`base-meeting-prep`、`base-review-export` | 置き換える前提の見本。そのままでも動く |

- **仕組みのスキル**は、ハブの決まった形（コミットの説明、記録、会話の要約）を作ったり読んだりします。会話の終わりのフック（`harness-session-archive`、`harness-record-links`）、統括と作業セッションの取り決め（指示書、作業の一覧、報告、試行の合流）、相談の記録（見せたもの、文字起こし、決まったこと、対応した作業をつなぐ）、履歴からの進捗の整理（`harness-progress-timeline`。導入前の経緯もこれで作る）は、研究によらず同じ形で動く必要があります。研究ごとの違いは、下の表のひな形・手引き・決まりで入れます。仕組みそのものを変えたいときは、ひな形を直します（下の「ひな形を直すとき」）。
- **仕組みのスキルと `CLAUDE.md` は、見本のスキルを名前で前提にしません。** 前提にするのは、その出力（`chats/` のファイルなど）です。見本を置き換えても、仕組みが動き続けるようにするためです。
- **見本のスキル**は、文字起こしの道具、相談やゼミの形式、見せる資料の形など、研究室や研究ごとに変わるものです。細かくは決めず、「こういうスキルがあると便利」という見本として置いています。各研究で置き換えてください。
- **全会話に効く既定**（`harness/base-rules.md` と、作業の会話が読む役の手引き `harness/roles/`）は、見本ではありません。何もしなくても全員の会話に効くので、誰にでも当てはまる最小限だけにしています。論文の書き方、見せる資料の作り方、実装の優先順位のような決まりは、各研究の `hub/rules.md` に書きます。

### 何をどこで直すか

| 直したいもの | 直す場所（研究の層） |
|---|---|
| `base-` のスキルの手順 | 写して研究独自のスキルにする（下の手順） |
| 複数のスキルや会話にまたがる決まり（書き方、議論の進め方） | `hub/rules.md`（どの既定を置き換えるかと理由を書く） |
| 記録の形（指示書、報告、相談、実験、会話の要約など） | `hub/templates/<名前>`（同じ名前があれば、ファイルごとひな形の代わりに使われる） |
| 作業の手引き | `hub/roles/<役>.md`（ひな形の手引きへの追記） |
| 新しいスキル | `harness-` でも `base-` でも始まらない名前で `.claude/skills/` に足す |
| Claude Code の設定 | `.claude/settings.local.json` |
| git から外したいもの | `.gitignore` の末尾の「この研究で足したもの」の下（理由のコメントを付ける） |

### `base-` のスキルを研究独自のスキルに置き換える

1. `.claude/skills/base-〇〇/` を、`harness-` でも `base-` でも始まらない名前のフォルダに写す（例：`thesis-export`）。
2. `SKILL.md` の `name` と `description` を直す。`description` には、この研究で `base-〇〇` の代わりに使うことと、元との違いを書く。
3. 本文の冒頭に「`base-〇〇` を元にした」と書く。
4. 手順やスクリプトを直す。
5. `hub/rules.md` の「研究独自のスキル・手引き・ひな形」に、代わりに使うことと理由を書く。
6. `.claude/settings.local.json` で元のスキルを隠す。似たスキルが並ぶと、Claude が元のほうを選ぶことがあるため。毎回の会話で読むスキルの一覧も短くなる。

   ```json
   { "skillOverrides": { "base-〇〇": "off" } }
   ```

   `settings.local.json` は git に入らない。別の PC にハブを移したときは、5 の記載から作り直す。
7. ハブの git にコミットする（説明は前・理由・きっかけ）。

`base-` のスキルを、その場で書き換えないでください。名前が「ひな形のもの」のままで正しく、研究で変えたものが研究独自のスキルにまとまります。

### 仕組みが読む部分

ひな形を `hub/templates/` で差し替えるときも、`base-` のスキルを置き換えるときも、次は残してください。仕組みのスキルがここを読みます。

- 記録の置き場所と名前：`chats/<名前>.md`、`records/meetings/<日付>_<題>/README.md`、`records/experiments/<id>/README.md`、`records/sessions/<開始日>_<ID の先頭 8 文字>.md`、`records/history/`、`hub/briefs/`、`hub/reports/`、`hub/research.md`、`papers/<論文の id>/` の下の `.md`（下のフォルダも含む。`export/` は除く）
- 各記録の「関連」の欄と、決定の印（`<a id="d-…"></a>`）
- 会話の要約の `auto` の囲みと、「要約した範囲」の行
- 文字起こしの冒頭の「相談の記録」の行

見本のスキルを置き換えるときは、出力を決まった場所に置き（文字起こしは `chats/`）、材料を作った後に `harness-meeting-record` に渡してください。文字起こしなら、用語集にも足してください。こうしておけば、見せる → 話す → 記録する → 対応する → 次に見せる、の流れとリンクは、置き換えても保たれます。つなぐ段が抜けても、`harness-record-links` が「相談の記録につながっていない文字起こし」として一覧に出します。

`CLAUDE.md` の約束（承認と決定、公開しないこと、現在の文書と履歴など）と仕組みのスキルは、研究の層では上書きできません。変えたいときは、ひな形そのものを直します（下の「ひな形を直すとき」）。

## ハーネスで決めていること・利用者が決めること

- **ハーネスで決めていること**：次の二つ。
  - ほかの会話や人がハブを読めるために、そろっている必要があるもの：ファイルの置き場所と形、持ち主、現在と履歴の分け方、コミットの説明、リンクの書き方
  - 取り返しがつかない・外に出る操作の止め方：push とマージは研究者の指示があるときだけ、ハブの履歴を書き換えない、元の資料を消さない、秘密
- **利用者が決めること**：いつ会話を分けるか、作業の粒度、統括をいつ替えるか、会話を閉じるか、ハブの控えを取るか（既定は取らない）など、状況や好みで答えが変わるもの。Claude は気づいたら提案するだけ。
- **アプリに依存する操作**（会話の起動、子のセッション、親から外す、アーカイブ）：決まりではなく、[harness/claude-code-notes.md](harness/claude-code-notes.md) に説明としてまとめた。

## 現在の文書と履歴

ハブの文書は二つに分かれます。

- **現在の文書**（`hub/` の現在地・プロフィール・決まり・用語集・決定・作業の一覧・研究の全体像と、`papers/`）：いま有効な決定・定義・状態だけを書く。いつ変えたか、前は何だったかは書かない。初めて見た人はこれだけを読めばよく、AI が過去の決定を現在の決定と取り違えることもない。
- **会話**：研究に関係する Claude Code の会話は、要約が `records/sessions/` に残る。生の記録は git の外に写し、要約から参照する。各決定から、決めた会話の要約へリンクできる。
- **履歴**：経緯は次のものに残る。日々の進捗と方針転換は、`harness-progress-timeline` でここから組み立てる。
  - git のコミットの説明（前・理由・きっかけ）
  - `records/` の日付つきの記録
  - `chats/`

詳しくは [CLAUDE.md](CLAUDE.md) の「現在の文書と履歴」。

## 秘密の扱い

- ハブには、指導教員の未発表の考えや、会話の文字起こしが入ります。現在地や論旨も含め、ハブの中身はすべてハブの git で管理しますが、公開しません。既定は**手元だけの git**です。リモートに置くなら非公開にしてください。
- **push の守り**：導入のときに、ハブの git に二つの守りを入れます。Claude でも人でも、どの道具から push しても効きます。
  - ひな形のリポジトリへの push を断つ。
  - push の前の確認（`harness/hooks/pre-push`）を有効にする。研究者が許可した非公開のリモート以外への push を止める。許可したリモートでも、履歴を書き換える push（force push）と、ブランチやタグの削除を止める。
- **文献の原文は git に入れません**（他の人の著作のため）。`literature/` で git に入るのは、参照の一覧（`index.md`）と案内だけです。原文と抜き書きは、手元の git の外に置きます。
- 公開のコードのリポジトリには、ハブの中身を書きません。つなぐためのファイル（`CLAUDE.local.md`）は、そのリポジトリの git に入らない形で置きます。
- 未発表の考えは、ウェブ検索の検索語にも入れません（`hub/profile.md` に、何を秘密とするかを書きます）。
- **ハブの中身を渡す AI は、`hub/profile.md` の「使う AI」の表にあるものだけです。** AI に作業を渡すと、中身がその AI の提供元に送られるためです。表に無い AI を初めて使うときは研究者に聞き、許可されたら、その会話の AI が表に足します。

## ひな形を直すとき

ハブの中でひな形を直して、ひな形のリポジトリに push しないでください。ハブの履歴には研究の中身が入っているので、ブランチを一つ送っただけでも中身が出ていきます。push の守りも、これを止めます。

1. **ひな形を別の場所に複製する。** 例：`git clone <ひな形の URL> research-harness-dev`
2. **その複製で、仕組みの部分だけを直す。** 直してよいのは次の場所。研究の中身は入れない。
   - `CLAUDE.md`、`AGENTS.md`、`INSTALL.md`、`README.md`、`LICENSE`
   - `.claude/`（`settings.json` と、`harness-`・`base-` のスキル）
   - `harness/`
   - `.gitattributes`、`.gitignore`（「この研究で足したもの」より上）
3. **ひな形に送る。** push するか、プルリクエストを出す。
4. **使っている人に知らせる。** 各自のハブでは、研究者が「ひな形の更新を取り込んで」と頼んだときに取り込む（`INSTALL.md` の 2）。Claude から更新を探しには行かない。

ハブで使っているうちに仕組みの改善を見つけたら、その差分を複製に写してから、2 に進みます。

## 必要なもの

- Claude Code。デスクトップ版なら、作業セッションの起動と報告の受け取りが自動になります。CLI でも、起動の 1 行をコピーすれば同じように動きます。
- git
- Python 3.10 以上（会話の記録、記録どうしのリンク、会話の履歴の取り出しのスクリプト。会話の終わりのフックは、3.10 より古い Python を使わない）

## 他の AI を使う人へ

使っている AI に、このリポジトリを導入したいと頼んでください。その AI は [AGENTS.md](AGENTS.md) から [harness/other-ai.md](harness/other-ai.md) をたどり、導入のときに、自分の機能に合わせた読み替えを研究の側に作ります。ひな形のファイルは書き換えません。読み替えの場所は `hub/profile.md` の「使う AI」の表に残ります。統括は Claude Code のまま、実装やレビューだけをほかの AI に任せることもできます（`harness/other-ai.md` の「初めて作業の会話として使われたとき」）。
